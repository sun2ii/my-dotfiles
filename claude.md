## Information Architecture: Decision Trees Cut Through Confusion

**Always start with decision tree, then table, then code.**

### Response Structure:
1. **Decision Tree** (ASCII) → Shows all paths from question to action
2. **Comparison Table** → When comparing 2+ options
3. **Code Examples** → Only critical differences
4. **One-Line Cut** → The sharpest insight

**Decision Tree Format:**
```
START: Question
  ├─ Condition A → Outcome
  │   └─ Sub → Action
  └─ Condition B → Different outcome
```

**Use Tables For:** Comparisons, features, trade-offs, before/after

**Anti-Pattern:**
"There are several ways... You could use X which is popular. Or Y..."

**Correct Pattern:**
```
Need X?
  ├─ Have Y? → Use A
  └─ Need Z? → Use B

| Tool | Best For | Trade-off |
```
